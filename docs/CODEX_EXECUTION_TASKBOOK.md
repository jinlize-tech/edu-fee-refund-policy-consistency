## 2. 用户、痛点与目标

- 用户：校长、财务人员、校区主管、客服主管、课程顾问
- 痛点：同一课包在价目表、合同、销售话术、系统设置和退款审批中可能出现不同折扣、有效期和退费标准。
- 目标：把课包、合同、价目表、优惠规则、退费制度与销售话术放入同一口径检查，生成差异表和统一规则建议。

|---|---|---|---|
| `course_packages` | 课包清单及价格 | array | 是 |
| `contract_rule_summary` | 合同规则摘要 | string | 是 |
| `published_price_list` | 对外价目表 | array | 是 |
| `sales_scripts` | 销售话术 | array | 是 |
| `refund_policy` | 退费制度 | string | 是 |

## 4. 工作流

1. 建立课包唯一编码
2. 抽取各渠道规则
3. 按情景比对
4. 标记冲突与不可执行条款
5. 设计复核用例
6. 输出统一规则和培训要点

## 6. 核心成果

- `规则一致性矩阵`
- `冲突清单`
- `建议统一口径`

## 7. 差异化与排重

- 与现有产品：现有退费测算计算单笔结果；本产品不计算某笔金额，而是审核所有对外规则是否同源一致。
- 排重检查：部分重叠但任务不同；本产品输出制度级规则审查，现有产品输出单笔测算或流程风控。
- 独立理由：只安装本产品即可完成规则一致性审查，不需要任何现有财务计算器。

## 8. 安全与人工门禁

- 复核角色：财务负责人与法律/合规人员
- 复核范围：收费、赠课、有效期、退费规则和对外口径的最终统一
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
